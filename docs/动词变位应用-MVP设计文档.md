## 1. 项目背景

### 1.1 用户画像（v2.0 修正）
- 西班牙语专业学生
- 设备：vivopad5pro 安卓平板（配 vivo Pen 手写笔）
- **编程背景：vibe coding 老手**——用过 Codex App、Cursor、Trae、Claude，会用 git/node
- "零基础"指**没系统学过编程语言**，但有 AI 工具使用经验，能直接让 AI 生成代码，不需要从零学 HTML/CSS/JS
- 学习策略：只背不规则动词变位，规则动词按变位规律归类记忆

### 1.2 核心痛点
1. 动词变位记不牢，放完假就忘
2. 错题遗忘，复习时被迫把所有动词所有时态全默一遍，效率随学习量增加而急剧下降
3. **用过 Anki 一学期，确认 Anki 无法满足需求**（详见 2.3）

### 1.3 项目目标
做一个平板用的动词变位学习工具，通过"用户自主归类 + 多维对比 + 艾宾浩斯复习"解决动词变位记忆效率问题。

## 2. 需求分析

### 2.1 原始想法
做一个平板工具，包含：
- 录入所有学过的动词及其变位
- 按自己想法和发现的规律分类命名
- 手写动词变位练习
- 错题集 + 艾宾浩斯记忆曲线提醒
- 自由录入课外/书本错题
- 笔记模块记规律口诀

### 2.2 澄清后的真实需求
经多轮讨论，真实需求明确为：
1. **完整变位库**，不需手动录入（Anki 没有，是主要弃用原因之一）
2. **时态规律速查模块**（reference 性质，不是卡片）——忘记时立刻查
3. **只背不规则动词**，规则动词按规律归类记忆
4. **多维对比**：
   - 横向：同一时态内对比相似变位动词，发现共性
   - 纵向：同一动词跨时态对比，看性格差异
5. **分类完全由用户自主归类**（不靠算法），分类体系随时更新，既用于发现规律也用于区分易混淆动词

### 2.3 为什么 Anki 不够用（具体）
| 用户需求 | Anki 能力 | 满足度 |
|---|---|---|
| 录入动词 + 变位 | 自定义模板 + CSV 导入；可下载现成西语变位共享牌组 | 完美 |
| 自由分类命名 | 标签系统自由命名，支持"父::子"伪嵌套 | 部分（扁平，复杂层级会乱） |
| 手写练习 | 安卓输入法手写识别可答题；无原笔迹画布、无压感 | 部分 |
| 错题集 + 艾宾浩斯提醒 | 核心就是间隔重复算法（FSRS/SM-2）；leech 机制自动标错题 | 完美 |
| 自由录入课外错题 | 随时新建卡片，打"#错题"标签 | 完美 |
| 笔记模块（规律 / 口诀） | 卡片"笔记"字段记短口诀够用；长规律总结体验差 | 部分 |

**总结**：6 项需求中 3 项完美、3 项部分、0 项做不到。但部分满足的 3 项（尤其是"完整变位库""自动对答案""多维对比"）是用户核心痛点，Anki 的卡片式结构本质上无法满足。

### 2.4 需求清单（6 大模块）
1. 动词库 + 自主分类（标签）
2. 时态规律速查模块
3. 键盘变位练习 + 自动判对错
4. 错题集
5. 艾宾浩斯复习提醒
6. 多维对比（横向 + 纵向）——**核心差异化**

### 4.3 多维对比模块详细设计（核心差异化）

#### 4.3.1 本质
用对比发现规律，用规律代替死记。把"用户脑子里在做的归类对比"外化成工具。

#### 4.3.2 Tab1 · 横向对比（管"广度"）
- **操作**：选一个标签 → 选一个时态 → 渲染矩阵
- **矩阵结构**：行 = 该标签下所有动词，列 = 6 人称（yo/tú/él/nosotros/vosotros/ellos）
- **目的**：看出这一组动词在该时态的共性
- **示例**：选"e→ue 易混组"标签 + 选"现在时" → poder/dormir/volver 等动词并列，词根 o→ue 变化一目了然

#### 4.3.3 Tab2 · 纵向对比（管"深度"）
- **操作**：选一个动词 → 渲染所有时态矩阵
- **矩阵结构**：行 = 所有时态（presente/pretérito/imperfecto/futuro/condicional/subjuntivo...），列 = 6 人称
- **目的**：看一个动词在不同时态的"性格差异"
- **示例**：poder 在现在时 o→ue（puedo），在 pretérito 完全换词根（pude），在 imperfecto 规则（podía）

#### 4.3.4 高亮策略
- **MVP 阶段**：不做自动高亮，用户自己看规律
- **进阶**：按 pattern 预定义变化规则硬编码高亮（如 stem-changing 类永远在词根元音）
- **远期**：算法 diff 变位与规则模板，自动标注变化部分

#### 4.3.5 Tab3 · 超级矩阵 Mega Matrix（v2.2 新增 · 广度 × 深度 立体交叉对比）

> **用户原话需求**："多个单词不同时态同时呈现在当前页面……左边的动词原形和上面的时态名称不移动，仅仅产生的变位可移动。有点像一个可以完整呈现所有变位所有时态的 excel 表格，我所有录入的动词都会出现在这个表格里。"

- **本质**：一张**超大的 N 行 × M 列矩阵**，行 = 动词库中所有动词，列 = 所有变位时态，每个单元格内嵌 6 人称小格。Excel 式冻结窗格：
  - **左列（动词原形） sticky left:0** —— 横向看更多时态时，动词永远看得见
  - **顶行（时态标题） sticky top:0** —— 纵向看更多动词时，时态永远看得见
  - **左上角交叉格 sticky top:0 + left:0，z-index 最高** —— 两个方向同时滚时 corner 不动
  - **中间变位区 overflow:auto** —— 横滚看更多时态，纵滚看更多动词
- **默认渲染规则**：
  - 默认显示 Indicativo 核心 5 时态（Presente / Pret Indef / Pret Imperf / Futuro / Subj Pres）
  - 默认显示前 20 只动词，底部提供「加载下 30 只」按钮（148 只目标量 4 次点击加载完）
  - 顶部 Select 一键切换：所有 15 时态 / 仅核心 3 / 仅虚拟式 / 仅命令式
- **颜色分层（视觉识别规则）**：
  - 🟥 **红底（.irreg）**：不规则词根 / 词干变化（stem-changing / 完全不规则 / Pretérito 特殊词干）
  - 🟨 **黄底（.spell）**：拼写变体（-car→c/qu / -gar→g/gu / -zar→z/c，发音不变、正字法改）
  - ⬜ **白底（默认）**：纯规则变位
- **交互找规律**：
  - 鼠标悬停任意动词行 → 整行 8% 主色淡底高亮 → 一眼看某动词跨 5 时态的完整表现
  - 工具条标签筛选（如"拼写 -car"）→ 立刻只留 -car 类动词 → 立刻确认：所有 -car 的 yo Pretérito 全是 c→qu（busqué/saqué/toqué）
  - 这就是用户**"跨动词、跨时态、一次性发现全局规律"**的核心载体
- **技术红线（血的教训 · P0 Bug）**：
  - ❌ 绝对禁止：拆成 header-table + body-table 两张表，用 JS resize 同步列宽。**100% 列宽错位（Experience ID 803672）**。
  - ✅ 唯一正确方案：**单 `<table>` + `position: sticky` + `table-layout: fixed`**，列宽完全由表格自身驱动。


### 4.4 标签 / 文件夹交互

#### 视觉呈现
标签模型在 UI 上完全呈现为"文件夹"体验：
```
[左侧：标签列表]          [右侧：当前标签下的动词]

e→ue 易混组 (8)        ←  点这个
e→ie 易混组 (12)
pretérito 地狱 (15)
ser/ir/saber 分不清 (3)
B2 错题 (20)
...
                              →  右侧显示这 8 个动词：
                                 poder / dormir / volver / resolver / morir ...
```

#### 标签比文件夹强的点
- 纯文件夹模型：一个动词只能放一个文件夹，需纠结放哪
- 标签模型：一个动词可同时属于多个"文件夹视图"
  - 例：poder 同时在"e→ue 易混组"（因 o→ue）、"pretérito 地狱"（因 pude 不规则）、"B2 错题"（因错过）
  - 从任何角度都能找到 poder

**视觉是"文件夹"，底层是"标签"——两全其美。**

### 4.5 时态规律速查模块
- 静态文本：每个时态的变位规律总结（如现在时 -ar 动词词尾 -o/-as/-a/-amos/-áis/-an）
- 拼写变体规则：-gar/-car/-zar 动词的 c→qu/g→gu/z→c
- stem-changing 规律：e→ie / o→ue / e→i 的触发条件（重音落在词根时变）
- 检索：按时态名/关键词查
- 难度：低（静态文本 + 简单检索）

### 4.6 键盘练习与判对错

#### 流程
1. 从某标签/全部动词中抽题（动词 + 时态 + 人称）
2. 用户键盘输入变位
3. 程序从 verbos 取正确答案比对
4. 判对错 → 错题入库

#### 判对错边界处理
- **重音符号不能忽略**：habló（过去时 él）≠ hablo（现在时 yo），áéíóú 必须精确比对
- **ñ 必须区分**：如 añadir 的 ñ
- **大小写**：统一转小写比对
- **首尾空格**：trim 处理
- 难度：中低（字符串规范化小细节）

### 4.7 错题集与艾宾浩斯

#### 错题入库
- 练习答错 → 自动生成错题记录（动词/时态/人称/正确答案/用户答案）
- 自动打"错题"标签，进入艾宾浩斯复习队列

#### 艾宾浩斯调度（SM-2 简化算法）
- 每个错题记录：lastReview / nextReview / interval / easeFactor
- 答对：interval 延长（1→3→7→15→30 天...），easeFactor 微调
- 答错：interval 重置为 1 天，wrongCount + 1
- 到期提醒：nextReview <= 当前时间的错题进入"今日复习"队列
- 难度：中（需学 SM-2 算法，但不难，网上有现成实现参考）

### 4.8 笔记模块（进阶）
- 每个动词可挂 notes 字段（已在数据模型中预留）
- 独立笔记页：记规律口诀、变位总结
- 难度：低

## 8. 设计修正记录

### 8.1 修正一：假设用户没用过 Anki
- **错误**：推荐"先试 Anki 一周再决定"
- **实际**：用户用过 Anki 一学期，明确知道不够用
- **修正**：收回"先试 Anki"建议，确认自开发合理

### 8.2 修正二：把"自主分类"听成"需要算法自动归类"
- **错误**：设计 pattern 自动归类、diff 高亮、聚类算法等不存在的难点，称"多维对比是阶段 3、零基础做不动"
- **实际**：用户明确"按自己想法自主归类"，分类完全由用户操作，软件只负责渲染矩阵
- **修正**：改为标签模型 + 用户手动归类 + 表格渲染，难度从"难"降到"低"，多维对比纳入 MVP

### 8.3 修正三：假设用户零基础（v2.0 新增）
- **错误**：按"零基础从零学 HTML/CSS/JS"评估，给 3-6 个月周期 + 阶段 1 学基础 1-2 月
- **实际**：用户是 vibe coding 老手，有 Codex App/Cursor/Trae/Claude 经验，会用 git/node。"零基础"指没系统学过编程语言，但有 AI 工具使用经验
- **修正**：删除阶段 1 学基础，改为一周冲刺计划（见第 6 章）

### 8.4 修正四：把 Codex 等同 CLI（v2.0 新增）
- **错误**：说"Codex 是 CLI 不是 IDE，调 UI 痛苦"，拿 Codex CLI 跟 Trae 对比
- **实际**：Codex 是产品家族（App/ChatGPT 内/CLI/IDE 扩展/cloud），Codex App 有 GUI、diff 审查、computer use、内置浏览器，完整能做网站
- **修正**：Codex App 是合理主力选择，不强推 Trae。两者范式差异在"监督式 vs 协同式"，不是"能不能做"

### 8.5 根因（v2.0 更新）
习惯性往"技术难"方向脑补 + **不核实产品形态就下结论** + **不问清用户背景就预设**。三次根因同类：
1. 不问就假设没用过 Anki
2. 不听原话就脑补需要算法
3. 不问就假设零基础
4. 不核实就说 Codex 是 CLI

**后续规则**：先问清用户背景 + 核实工具实际形态，再推演设计。

#### 10.3.1 错题"两文件夹"模型详解（C2 核心设计）

错题记录不分两个真文件夹，用 `status` 字段实现两个视图：

```js
// 错题记录（v2.1 更新）
{
  verbId: "poder",
  tense: "preterito",
  person: "yo",
  correctAnswer: "pude",
  userAnswer: "podí",
  wrongCount: 2,              // 永远累加，不重置
  consecutiveCorrect: 0,      // 连续答对计数，答错归 0
  status: "active",           // active=复习中 / graduated=已毕业
  // SM-2 调度字段
  lastReview: "...",
  nextReview: "...",
  interval: 1,
  easeFactor: 2.5,
  createdAt: "..."            // 永久保留，不删除
}
```

**两个视图**：
- **错题历史**（永久）：显示所有错题（active + graduated），随时查"我常错过哪些"。永不删除。
- **今日复习**（动态）：只显示 `status === "active"` 且 `nextReview <= 今天`。连续答对 3 次的错题 `status` 改为 `graduated`，从复习队列移出，但记录保留在错题历史里。

**调度逻辑**：
- 答对：`consecutiveCorrect +1`，`interval` 延长（1→3→7→15→30 天），`easeFactor` 微调
- 答错：`wrongCount +1`，`consecutiveCorrect` 归 0，`interval` 重置为 1 天
- `consecutiveCorrect >= 3` → `status = "graduated"`，移出复习队列，记录保留

**为什么这个设计好**：分清了"记忆留痕"（历史）和"复习调度"（队列）是两件事。Anki 的 leech 机制直接暂停卡片，没有这个分离。用户本能地切对了这一刀。

### 12.2 犀利批判（自我攻击，避免你骂我）

1. **你最容易犯的一个错误**：觉得"超级矩阵就是把横向+纵向拼起来"，于是分别做横向和纵向，然后**偷工减料复用原组件网格**。这是错的——超级矩阵的 6 人称是**每个单元格内部的 per-6 grid**，不是外部列。直接复用横向矩阵的"列=6 人称"结构，会直接把时态撑爆成 6 列/时态，15 时态 = 90 列，完全不可用。**超级矩阵单元格（td）内必须是 6 行小格 per-6，不能展开成表外列。**
2. **另一个坑**：你可能会想"把列宽做得紧一点让 15 时态都挤在一屏不用横滚"。**千万别。** 那样每个 tense 列宽度 < 100px，6 人称 + 重音字符会换行重叠。时态列宽**下限 150px**，默认 Indicativo 5 时态 = 750px（882px main 区宽剩 132px 给 verb 110 + 右侧 margin 22，刚好）。
3. **第三坑**：spell 颜色标记（buscar→busqué / lanzar→lancé）你会想"除了 Pret Indefinido yo，Subjuntivo Presente 全 6 人称也变对吧？"——对，lanzar Subj Pres 的 6 人称全是 lance/lances/lance/lancemos/lancéis/lancen，都是 z→c，全 6 格都要黄底。**千万别只标记第一人称。** 会被你自己骂死。
4. **最后一个死坑**：你做完第一版后会想"滚动条占 14px，所以表格实际宽度少 14px，应该把 mega-wrap 宽度 -14"。**不要手动抠像素。** overflow:auto 的滚动条宽在 Chrome Android/Windows/macOS 上都不一样（mac 透明不占位）。抠像素会导致某端对齐错误。相信 `table-layout: fixed` + `min-width: max-content`，让浏览器自己管。
