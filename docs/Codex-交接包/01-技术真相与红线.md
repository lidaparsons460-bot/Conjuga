## 2. 数据模型（字段名有历史分裂，新代码照此表用）

| 表 | 字段（真实） | 备注 |
|---|---|---|
| verbs | `{ id, infinitive, tags[], notes, createdAt }` | **字段名是英文 `infinitive`** |
| tags | `{ id, category, name }` | category ∈ 错题组/规律组/口诀组（硬编码大类） |
| mistakes | `{ key, infinitivo, mood, tense, streak, wrongCount, lastWrong, dueAt, graduated }` | **字段名是西语 `infinitivo`**；key = `inf|mood|tense` |
| notes | `{ id, group, title, content, verbs[], createdAt, updatedAt }` | group ∈ 规律/口诀/易混 |

⚠️ **命名陷阱（本项目历史上最疼的一刀）**：verbs 用 `infinitive`、mistakes 用 `infinitivo`，两个模块各自正确、接口对不上时 JS 静默 undefined 不报错。曾有 5 处混用导致"练习抽不出题/首页最近录入为空/纵向对比下拉空白"的连环 bug，已全修。**新代码：verbs 域用 infinitive，mistakes 域用 infinitivo，绝不新造第三种拼法。**
另：`db.js` 里 verbs 表的索引声明写的是 `infinitivo` 但实际字段是 `infinitive`——该索引是死的（查询走内存遍历，无功能影响），属已知瑕疵，重构时顺手改，不急。

## 3. verbos 包（数据源）的三个坑

1. **人称键名无重音**：是 `tu / ud / uds`，不是 `tú / él / ellos`。useVerbs.js 里已做映射，别在视图层直接取原始键。
2. **imperativo 是顶层字段**：`indicativo` / `subjuntivo` 是嵌套对象，但 `imperativo` 的肯定/否定式是顶层 `afirmativo` / `negativo`，且只有 4 人称（tu/vosotros/ud/uds，无 yo/nosotros）——**抽题和矩阵渲染都要跳过 imperativo 的 yo/nosotros**。
3. **`regular: boolean` 字段存在但只是动词级粒度**——精确到时态/人称的不规则判定不要用它，用 useIrregularRules.js（见第 5 节）。

## 4. 三色分级规则（超级矩阵与横向对比共用）

由 `useIrregularRules.js` 的 classifyTense 逐格计算，**零硬编码动词白名单**：

- ⚪ 白：实际变位 == 规则推导变位
- 🟨 黄：仅正字法差异（-car→que / -gar→gue / -zar→ce / -guir→go 等）
- 🟥 红：其他（词干变化、完全不规则）

反身动词（带 se）整体退化为动词级红标——已知妥协，MVP 接受。

## 5. 核心机制速记

- **SM-2 简化**：答错→明天到期，复习间隔梯度 [1,2,4,7,15,30] 天；连对 3 次毕业（graduated）；毕业卡可"复发重置"
- **抽题**：7 个简单时态 × 6 人称（完成时态刻意排除：考的是 haber 不是动词本身；imperativo 排除无人称项）
- **判定三档**：全等 ✓ / 仅重音差异（á é í ó ú ñ）✓但提醒 / 错 ✕ 且标出差异位
- **超级矩阵**：单表结构，th sticky top、动词列 sticky left、交叉格 z-index:3；`table-layout: fixed` + colgroup 同步列宽；首屏 20 只 + 每次加载 30；支持时态组切换（核心3/Ind5/仅虚拟式/全17时态）与标签、搜索筛选；组模式（笔记整组跳转 `?verbs=a,b,c`）独占、隐藏常规筛选
- **备份**：JSON 导出（文件名带日期）；导入为合并覆盖（按 id/key），完成后显示备份时间
- **PWA**：sw.js 构建产物 cache-first / 页面 network-first，**仅 https 注册**（localhost 也算安全上下文，局域网 IP 不算）

## 7. 编码红线（违反 = 必须返工）

1. **样式只准引用 tokens.css 令牌**，禁止硬编码 hex/px（暗态模式靠令牌翻转实现，硬编码会破暗色）
2. **超级矩阵禁止拆双表同步列宽**——单表 sticky 是架构决策，拆表是已被否决的方案（列宽错位之源）
3. **超级矩阵时态列内的 6 人称是单元格内部 6 行小格**（td 内 per-6），不展开为外层列
4. **拼写变体标记必须覆盖所有受影响人称**（如 lanzar 虚拟式全 6 人称 z→c），不只标 yo
5. **触摸目标 ≥ 48px**（平板主用），z-index 遵循 tokens 层级表
6. **文案面向第一次打开应用的用户**——禁止开发者内部梗（曾有"去答错几题（故意的也行）"这类自嗨文案，已全站整改过一轮）
7. **数据流转改动必须构造真实数据全链路验证**，"编译 200"不算数（见第 6 节血泪）

## 8. 有意为之的设计妥协（别当 bug "修"）

- 重音宽判（算对但点名提醒）——为降低平板软键盘长按重音的摩擦，非疏忽
- 完成时态不进抽题池——见第 5 节理由
- 无账号、无云同步——单用户单设备 + JSON 备份的"方案 2 主从模式"，已评估为当前最优
- 删除动词无二次确认（错题/笔记有）——单用户低风险，故意放行
- 笔记纯文本无 Markdown——MVP 范围控制
- Tab2 纵向对比的动词选择是 select 下拉——已知不优雅，P2
